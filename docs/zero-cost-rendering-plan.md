# Bharat AI — Zero-Paid-Cost Rendering Plan

## Product requirement
The core app must not require paid API credits, paid tokens, a subscription, or a paid GPU endpoint. Open-source model weights and source code do not make compute free: GPU time, storage, bandwidth and hosted services can still be metered. The product must disclose those limits.

## Current repository state (audited 2026-11-09)
- React + Vite client with script, voice, storyboard, scene-player and export foundations.
- Browser script generation is available as a no-key fallback.
- Browser Web Speech is available where supported; it is not voice cloning.
- The Wan 2.1 1.3B ZeroGPU worker exists under workers/hf-zerogpu/.
- The frontend adapter speaks the Gradio queue API.
- The current video agent attempts at most one short clip per run. The worker reserves 120–240 GPU seconds per request; this is a best-effort free-tier path, not a route to two minutes of diffusion footage.
- The worker has not been validated against a live deployed Space in this repository. Source code alone does not prove GPU inference works.
- The existing application can produce a storyboard/local preview without GPU; that is not equivalent to photorealistic model-generated footage.

## Recommended execution tiers
### Tier 1 — Local GPU (preferred, no service credits)
Run ComfyUI locally and install the official Wan video workflow/model weights that fit the user's hardware. Bharat AI should connect to a user-owned ComfyUI endpoint on the same machine or trusted LAN. This avoids per-request API billing, but requires a compatible GPU, disk space, electricity and local setup. It is not compute-free.

### Tier 2 — Public free GPU quota (best-effort)
Use a public free-tier worker only when its published quota and current availability permit. The Hugging Face ZeroGPU worker is optional, not a guaranteed production service. Its published free quota is limited and shared; cold starts and queue delays are expected. Never hard-code a quota as remaining balance.

### Tier 3 — No GPU available
Allow script, shot planning, local narration where browser support exists, captioning, image/clip import and local MP4 assembly. Label any output containing stills or motion graphics as a locally assembled video. Do not claim that it is fully generated by a video diffusion model.

## Two-minute deliverable definition
A two-minute MP4 can be assembled from a sequence of short generated shots plus narration, captions, transitions and imported/created stills. It must include a render manifest that lists each segment's source and provenance. The app must not claim 120 seconds of diffusion-generated motion unless 120 seconds of actual model-generated footage exists.

A fully diffusion-generated two-minute film is a different and much heavier compute task. The current free ZeroGPU allowance and current worker implementation do not establish that this is possible at ₹0. A local GPU path or substantially more free compute would be needed for sustained generative footage.

## Implementation sequence
1. Make provenance and worker status explicit in the UI.
2. Make local ComfyUI a first-class optional adapter; do not require hosted paid APIs.
3. Keep the Wan ZeroGPU adapter as a best-effort fallback and cap requests to its real published quota.
4. Add a local assembly stage that can concatenate clips, still-image motion, narration, captions and transitions into MP4.
5. Produce a JSON render manifest with per-segment provenance and exact durations.
6. Add resume/retry behavior so a failed GPU call does not lose already generated scenes.
7. Validate model inference on a live worker before marking the worker as operational.
8. Run a complete 120-second local scene export test and verify duration, playable browser recording and audio-track provenance. A true MP4 mux and two minutes of diffusion-generated footage remain separate deliverables.

## Acceptance criteria
- No mandatory paid key, token, subscription or API.
- No secrets in client-side code.
- No fabricated GPU quota or progress.
- A missing worker produces an explicit blocked state, not a fake success.
- A successful local scene render produces a downloadable browser-recorded video; the current browser recorder may produce WebM rather than MP4.
- The 120-second deliverable is checked for actual duration and playable media.
- Every generation/export status distinguishes model-generated clips from local assembly.
